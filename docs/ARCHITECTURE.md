# 구조와 확장 지점

## 현재 흐름

```mermaid
flowchart LR
    UI[브라우저] --> API[FastAPI 계약]
    API --> DB[(SQLite 작업·이력)]
    API --> Q[스레드 실행 큐]
    Q --> N[문서 정규화]
    N --> A[기준 추출 역할]
    A --> R[근거 검색 도구]
    R --> B[검토·수정안 역할]
    B --> V[근거·스키마 검사]
    V --> C[독립 검증 역할]
    C --> H[사람 확인]
    H --> DB
    DB --> O[보고서·평가]
```

실제 모델 모드에서는 추출·검토·검증이 서로 다른 지시문과 JSON 계약으로 각각 모델을 호출합니다. 독립된 역할 호출이며 동일한 모델을 공유할 수도 있습니다. 문서 정규화·검색·근거 검사는 결정적 코드입니다. 일반 노드 수를 에이전트 수라고 부르지 않습니다.

## 코드 경계

| 파일 | 책임 | 다음 확장 |
| --- | --- | --- |
| models.py | 입력·에이전트 출력·검토 결정의 엄격한 계약 | 필드 변경 시 호환성 테스트 |
| packs.py | 등록된 업무 폴더 로딩·지시문 hash | 검수된 팩 버전 저장소 |
| retrieval.py | 문단·버전·ID 생성, 어휘 검색 | 같은 결과 계약의 임베딩 검색 |
| providers.py | 예제 재생 / 실제 모델 HTTP | 엔드포인트별 구조화 출력 호환 |
| validation.py | 원문 인용·역할·범위·기준 수 검사 | 도메인별 결정 규칙 별도 도구 |
| workflow.py | 단계 실행·이력·실패 상태 | 별도 durable worker |
| store.py | 트랜잭션·중복 요청·revision·audit | PostgreSQL·조직/사용자 구분 |
| reports.py | 결과물·운영 집계 | 제출 양식별 내보내기 |
| evaluation.py / dataset.py | 평가·누출 검사·SFT 내보내기 | 독립 정답셋·사람 검수 도구 |

## 실행 상태

queued → running → awaiting_review → completed. 실패는 failed에 저장합니다. 서버 재시작 때 이전 queued/running은 INTERRUPTED 실패로 표시합니다. 자동 재실행으로 모델 호출 비용을 중복 발생시키지 않습니다.

완료는 모든 **검토 의견에 사람이 결정을 남겼다**는 뜻입니다. 문서의 모든 문제를 해결했다거나 실제 시스템 시험에 통과했다는 뜻이 아닙니다.

동일 Idempotency-Key와 같은 입력은 기존 실행을 반환합니다. 같은 키에 다른 입력은 409입니다. 검토 의견 저장은 현재 revision을 요구하고, 충돌 시 409를 반환하며 기존 변경을 덮어쓰지 않습니다.

## 근거 경계

- 기준 추출은 basis 문서의 실제 인용이 있어야 합니다.
- 검토 근거는 해당 역할에 전달한 target 청크 안에 있어야 합니다.
- 인용 ID와 quote가 원문에 없으면 제거하고 needs_review로 바꿉니다.
- missing은 입력 문서가 완전하고 대상 전체 청크를 전달했을 때만 허용합니다.
- 일부 검색에서 못 찾았다는 이유로 전체 문서의 부재를 확정하지 않습니다.
- 의미적 검증 역할은 문제를 발견하면 확인 필요로 내립니다. 구조 검사 실패를 덮어써서 긍정 판정으로 올리지 않습니다.

문서의 명령문은 데이터로 취급하라는 공통 지시문을 넣었지만, 이것만으로 프롬프트 공격이 완전히 차단되었다고 주장하지 않습니다. 외부 쓰기 도구는 현재 없습니다.

## 저장과 관측

실행마다 입력 문서 스냅샷, 문서 버전, 입력 hash, 팩 hash, 역할별 프롬프트 hash, 모델 이름, 호출 시간, 제공된 token usage를 남깁니다. 비용은 실제 요금 정보가 없으므로 null입니다. 데모에서 토큰 사용량이나 모델 정확도를 만들어 표시하지 않습니다.

현재 .data는 암호화 저장소가 아니며 조직 인증도 없습니다. 로컬 개발에 쓰고, 팀 공유 서버로 전환할 때 사용자·조직·접근 권한과 보관 정책을 구현합니다. SQLite와 메모리 실행 큐를 사용하는 동안 서버 worker는 1개로 유지합니다.
