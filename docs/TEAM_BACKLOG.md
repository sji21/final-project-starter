# 5인팀 인계 백로그

역할은 초안입니다. 팀원 역량에 맞춰 교환할 수 있습니다. 이미 공통 기반이 있는 만큼 첫 주는 주제·자료·실제 모델의 연결에 집중합니다.

| ID | 우선 | 담당 / 검토 | 작업 | 완료 조건 |
| --- | --- | --- | --- | --- |
| P-01 | P0 | PM / 전체 | 주제·사용자·시나리오 확정 | 실제 입력 3건과 기대 결과를 팀이 설명 |
| D-01 | P0 | 데이터 / PM | 원천 자료 확보·이용 조건 | 자료 목록·버전·이용 범위·검토자 기록 |
| D-02 | P0 | 데이터 / 에이전트 | 판정 기준 교차 검토 | 팀원 불일치 사례를 정리하고 라벨 정의 고정 |
| A-01 | P0 | 에이전트 / 백엔드 | 새 도메인 팩 | 코어 변경 없이 예제·원문·보고서 동작 |
| M-01 | P0 | sLLM / 에이전트 | 베이스 모델 endpoint 연결 | 세 역할의 유효 JSON, 실제 토큰·지연 기록 |
| E-01 | P0 | PM+데이터 / 에이전트 | 개발·검증·최종 평가 분리 | 그룹 누출 검사와 검토 근거 완료 |
| U-01 | P1 | 프런트 / PM | 실제 사용자 용어·화면 개선 | 사용자 3명 이상이 대표 흐름을 따라가며 의견 기록 |
| R-01 | P1 | 에이전트 / 데이터 | 어휘 검색 대비 임베딩 검색 | 동일 평가의 근거 recall·지연 비교 |
| M-02 | P1 | sLLM / 백엔드 | 소량 학습·어댑터 서빙 | checkpoint 재로딩, 동일 사례 전후 결과 |
| B-01 | P1 | 백엔드 / 에이전트 | 공유 환경 인증·권한 | 사용자·프로젝트 격리와 접근 거절 검사 |
| B-02 | P1 | 백엔드 / 프런트 | durable worker·공유 DB | 재시작·중복 요청·동시 검토 정책 검증 |
| D-03 | P1 | 데이터 / sLLM | 실제 SFT 자료 확대 | approved 데이터·학습 manifest·오류 유형 기록 |
| F-01 | P2 | 백엔드 / PM | 추가 파일 형식 | 실제 자료 형식 하나를 안정적으로 추출 |
| E-02 | P1 | PM / 전체 | 업무 가치 평가 | 품질을 유지하며 시간·수정량 비교 |
| P-02 | P1 | PM / 전체 | 발표·증거 패키지 | 모델·데이터·평가·실패·복구 증거 연결 |

P0는 첫 통합 전에 필요한 일, P1은 핵심 완성, P2는 여유가 있을 때 추가할 일입니다. 현재 없거나 검증하지 않은 기능은 “이미 완료”로 이동하지 않습니다.

공통 기반 자체의 테스트와 API 문서를 먼저 읽고 각자 다른 스키마로 병렬 구현하지 않습니다. 프런트·에이전트·sLLM 담당이 동일한 JSON 예제를 공유합니다.
